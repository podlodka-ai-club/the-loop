# Витрина Loci

Один экран: кадр из корпуса, карта с истиной и ответом, режим памяти, уроки,
которые ушли в промпт. Живых вызовов нет — вся страница читает
`public/showcase.json`.

```bash
npm install
npm run dev      # localhost:3000
npm run build    # статический экспорт в out/, открывается любым файловым сервером
```

## Откуда данные

`public/showcase.json` собирает `src/showcase.ts` в корне репозитория из выгрузок
`data/runs/`:

```bash
cd ..
npm run showcase          # 25 кадров + картинки -> demo/public/
```

Пересборка ничего не считает заново — только перечитывает файлы прогонов, поэтому
запустить её нельзя так, чтобы числа поехали.

Сами кадры и `showcase.json` закоммичены: демка должна запускаться без датасета
OSV-5M в 116 МБ, который ей больше ни для чего не нужен.

## Режимы

| Режим | Прогон | Что показывает |
|---|---|---|
| Без памяти | `baseline-863` | исходный промпт агента |
| Порог 2 | `memory-threshold2-430` и два прогона витрины | top-5 с порогом в два редких совпадения; слайдер меняет объём стора: 25, 48, 73 урока |
| Вся память | `memory-all-73-863` | все 73 урока в каждом промпте |
| Подменённая | `shuffled-threshold2-430` | те же уроки, привязанные к чужим регионам |

Слайдер работает только в режиме «Порог 2»: остальные режимы определены своим
стором и объём не варьируют.

## Что читать в цифрах

Сводка внизу — по полным прогонам корпуса (863 кадра или замороженный префикс в
430), а не по 25 кадрам витрины. Двадцать пять кадров выбраны так, чтобы механизм
было видно, и средним ничего быть не могут. Две строки помечены «только витрина»:
на снапшотах в 25 и 48 уроков полного прогона не делали.

Притяжение — доля предсказаний, попавших в один из 61 региона, названного уроками.
Без памяти 5%, со всеми 73 уроками 75%. Это и есть эффект: список названных мест в
промпте сужает область ответа независимо от того, применим ли урок к кадру.
