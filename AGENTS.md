# AGENTS.md

Инструкции для агентов, работающих в репозитории Loci.

## Контекст проекта

Loci — фоновый агент, который определяет место съёмки по фотографии и накапливает опыт во внешней
памяти. Основной артефакт — документация в `docs/`. Workflow памяти пока спроектированы, но не
реализованы. Исполняемый код есть только у benchmark в `src/`: слепой вызов модели на одном фото,
метрики OSV-5M и Phoenix-эксперимент.

## Структура репозитория

- `README.md` — краткое описание проекта и карта документации.
- `docs/index.md` — точка входа в OKF-бандл.
- `docs/concept.md` — назначение и общая модель Loci.
- `docs/benchmark/` — выборка OSV-5M, метрики и порядок воспроизведения прогона.
- `docs/data/` — источники изображений и план заморозки датасета.
- `docs/research/` — исследования процесса визуальной геолокации.
- `docs/tools/` — контракты memory store, retrieval и геокодеров.
- `docs/workflows/` — контракты inference, locate, train и evaluation.
- `docs/questions.md` — вопросы по архитектуре и процессам, требующие решения.
- `src/` — код benchmark: агент, задача, метрики, эксперимент.
- `benchmark/samples/` — замороженные списки id, по которым считается benchmark.
- `.env.example` — переменные окружения; реальный `.env` не коммитится.

## Работа с документацией

- `docs/` — knowledge bundle в формате OKF: markdown-файлы с YAML-frontmatter. Для концептов
  обязательным является непустое поле `type`; поля `title`, `description` и `timestamp` добавляй
  всегда, когда создаёшь новый документ.
- При добавлении, удалении или переименовании концепта обновляй `index.md` соответствующей
  директории и корневой `docs/index.md` в том же изменении.
- Перекрёстные ссылки пиши от корня бандла, например `[модели workflow](/workflows/models.md)`.
  После перемещения или удаления файла проверь все ссылки на него.
- `index.md` предназначен для навигации и не содержит frontmatter, кроме корневого
  `docs/index.md` с `okf_version: "0.1"`.
- `log.md` намеренно не ведётся: историю изменений предоставляет git.
- Контракты в `docs/tools/` и `docs/workflows/` должны оставаться согласованными: при изменении
  модели обновляй связанные workflow и индексы.

## Работа с кодом

- Секреты только в `.env`. Ключ в исходнике, в тесте или в документации — ошибка.
- Изображения, CSV датасета и база Phoenix живут в `tmp/`, которая в `.gitignore`.
- `src/experiment.ts` не делает новый жребий выборки. Список id приходит из manifest, иначе копии
  репозитория с разными shard изображений посчитают разные числа под одним именем.
- Новую выборку создавай командой `node src/sample.ts --freeze` и коммить отдельным изменением.
- При изменении метрик, prompt или обрезки кадра обнови базовые числа в
  `docs/benchmark/osv5m-eval.md` в том же изменении.

## Проверка перед коммитом

После изменений в `docs/` запусти валидатор OKF:

```bash
python3 ~/.claude/plugins/cache/writer-assistant/plan/2.8.0/skills/okf/scripts/validate_okf.py docs
```

Ожидаемый результат — `CONFORMANT` без ошибок. Дополнительно проверь `git diff --check` и поиск
ссылок на удалённые файлы. Скрипт валидатора находится в кэше плагина и может отсутствовать в
других окружениях; если он недоступен, сообщи об этом явно.

После изменений в `src/` запусти проверку типов и проверку выборки:

```bash
npm run typecheck
npm run sample
```
