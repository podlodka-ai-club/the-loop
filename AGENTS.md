# AGENTS.md

Инструкции для агентов, работающих в репозитории Loci.

## Контекст проекта

Loci — фоновый агент, который определяет место съёмки по фотографии и накапливает опыт во внешней
памяти. Основной артефакт — документация в `docs/`. Workflow памяти пока спроектированы, но не
реализованы. Исполняемый код есть только у benchmark в `src/`: слепой вызов модели на одном фото,
метрики OSV-5M и Phoenix-эксперимент.

## Структура репозитория

- `README.md` — краткое описание проекта и карта документации.
- `docs/index.md` — точка входа в OKF-бандл.
- `docs/concept.md` — назначение и общая модель Loci.
- `docs/benchmark/` — выборка OSV-5M, метрики и порядок воспроизведения прогона.
- `docs/data/` — источники изображений и план заморозки датасета.
- `docs/research/` — исследования процесса визуальной геолокации.
- `docs/tools/` — контракты memory store, retrieval и геокодеров.
- `docs/workflows/` — контракты inference, locate, train и evaluation.
- `docs/questions.md` — вопросы по архитектуре и процессам, требующие решения.
- `src/` — код benchmark: агент, задача, метрики, эксперимент.
- `benchmark/samples/` — замороженные списки id, по которым считается benchmark, и решения осмотра.
- `benchmark/images/` — сами кадры корпусов, коммитятся; собирает `npm run collect`.
- `.env.example` — переменные окружения; реальный `.env` не коммитится.

## Работа с документацией

- `docs/` — knowledge bundle в формате OKF: markdown-файлы с YAML-frontmatter. Для концептов
  обязательным является непустое поле `type`; поля `title`, `description` и `timestamp` добавляй
  всегда, когда создаёшь новый документ.
- При добавлении, удалении или переименовании концепта обновляй `index.md` соответствующей
  директории и корневой `docs/index.md` в том же изменении.
- Перекрёстные ссылки пиши от корня бандла, например `[модели workflow](/workflows/models.md)`.
  После перемещения или удаления файла проверь все ссылки на него.
- `index.md` предназначен для навигации и не содержит frontmatter, кроме корневого
  `docs/index.md` с `okf_version: "0.1"`.
- `log.md` намеренно не ведётся: историю изменений предоставляет git.
- Контракты в `docs/tools/` и `docs/workflows/` должны оставаться согласованными: при изменении
  модели обновляй связанные workflow и индексы.

## Работа с кодом

- Секреты только в `.env`. Ключ в исходнике, в тесте или в документации — ошибка.
- Изображения, CSV датасета и база Phoenix живут в `tmp/`, которая в `.gitignore`.
- `src/experiment.ts` и `src/train.ts` не делают новый жребий. Список id приходит из manifest,
  иначе копии репозитория с разными shard изображений посчитают разные числа под одним именем.
- Корпусов два, и они не пересекаются. Роль записана в manifest: `eval` для замера, `train` для
  дистилляции памяти. Не подменяй файл флагом `--manifest`, чтобы «быстро прогнать» — запуск с
  чужой ролью останавливается намеренно.
- Новые корпуса создавай одной командой `node src/sample.ts --freeze` и коммить отдельным
  изменением. Заморозка по одному корпусу за раз не даёт им взаимной ссылки.
- Пул корпусов — `benchmark/samples/reviewed.txt`, и ничего больше. Кадр, которого никто не
  смотрел, в корпус не попадает: автоматика не видит перевёрнутый кадр, а именно за этим
  осмотр и нужен. Refill-а больше нет, поэтому дефект при заморозке останавливает её, а не
  стоит одного кандидата.
- Пул делится на два корпуса не двумя жребиями, а разбиением (`src/split.ts`). Половины
  сходятся по странам, потому что урок про Кению нечем проверить, если в eval-корпусе Кении
  нет. Двигаются не кадры, а группы: кадры с общим `sequence`, автором или ячейкой 25 км
  неразделимы, поэтому правило разделения выполняется по построению.
- `npm run sample` печатает `country gap` рядом с `floor` — наименьшим разрывом, который этот
  пул допускает. Равенство означает, что разбиение оптимально; `gap` выше `floor` — что нет.
- Кадры не обрезаются. Кадр с выжженной надписью отбраковывается целиком. Меняя
  `src/screen.ts`, ты меняешь состав корпусов, поэтому их надо перезаморозить, а базовые
  числа пересчитать.
- `benchmark/samples/rejected.txt` — список кадров, забракованных вручную. Строка:
  `<id> <причина>`; причина обязательна. Файл сильнее `reviewed.txt`: кадр, одобренный и
  потом отброшенный, назван в обоих, и решает более позднее решение. После правки файла
  перезаморозь корпуса: `npm run sample` падает, пока забракованный кадр остаётся в корпусе,
  и пока одобренный кадр остаётся вне корпусов.
- `npm run review` — локальное приложение ручного просмотра кадров (`src/review.ts`,
  `src/review.html`). Стрелка вверх оставляет кадр, вниз отбраковывает его с причиной `drop`,
  влево и вправо поворачивают кадр на 90°. Свайп в ту же сторону делает то же самое; порог —
  48 пикселей по преобладающей оси. Направление решает одна функция `act`, поэтому клавиша и
  свайп не могут разойтись. Каждое решение сразу пишется в файл, поэтому сессию можно
  прервать: `rejected.txt` — отброшенные, `benchmark/samples/reviewed.txt` — просмотренные
  и оставленные, `benchmark/samples/rotated.txt` — повороты. Кадр из любого из этих файлов
  второй раз не показывается; чтобы вернуть его, удали строку.
- `npm run review -- --tailnet` публикует приложение в tailnet через `tailscale serve`.
  Без флага ничего наружу не открывается. Прямой адрес `http://<tailnet-ip>:5173` не
  работает: правила Windows Firewall для `node.exe` покрывают только профиль Public, а
  интерфейс Tailscale — Private. Порт прокси берётся из процесса, поэтому он не может
  указывать на порт, где ничего не слушает.
- `benchmark/samples/rotated.txt` — источник правды о поворотах, строка `<id> <градусы по часовой>`.
  Поворот считается от исходного кадра датасета, а не от уже повёрнутого файла. Его применяют
  `src/image.ts` (кадр для модели) и `src/collect.ts` (копии в `benchmark/images/`).
  Не правь jpg вручную: перезапись копии вернёт кадр к состоянию из этого файла.
- У забракованного кадра строки в `rotated.txt` нет: он ни в одном корпусе, поворот никто не
  прочитает. `npm run review` удаляет строку сам, когда кадр отбраковывают после поворота.
- Поворот меняет пиксели, но не отпечаток корпуса, поэтому кадр остаётся в корпусе, а базовые
  числа надо пересчитать так же, как после отбраковки.
- `npm run collect` — единственный писатель `benchmark/images/`. Он собирает папку заново по
  манифестам, применяет повороты, сверяет каждую копию по sha256, переносит забракованные
  кадры в `tmp/dropped/` и удаляет всё остальное. Кадры не теряются: источник в
  `tmp/datasets/osv5m/`.
- При изменении метрик, prompt или правил отбраковки обнови базовые числа в
  `docs/benchmark/osv5m-eval.md` в том же изменении.

## Проверка перед коммитом

После изменений в `docs/` запусти валидатор OKF:

```bash
python3 ~/.claude/plugins/cache/writer-assistant/plan/2.8.0/skills/okf/scripts/validate_okf.py docs
```

Ожидаемый результат — `CONFORMANT` без ошибок. Дополнительно проверь `git diff --check` и поиск
ссылок на удалённые файлы. Скрипт валидатора находится в кэше плагина и может отсутствовать в
других окружениях; если он недоступен, сообщи об этом явно.

После изменений в `src/` запусти проверку типов и проверку выборки:

```bash
npm run typecheck
npm run sample
```

- Идентификаторы, имена файлов, поля контрактов и примеры JSON — на английском, если это часть
  технического интерфейса.

  workflow или данные.
