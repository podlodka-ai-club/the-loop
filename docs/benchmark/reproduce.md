# Воспроизведение прогона

Инструкция повторяет базовый прогон из [Оценка агента на OSV-5M](osv5m-eval.md) на
чистой копии репозитория. Шаги 1–5 не тратят деньги. Первый платный вызов происходит на
шаге 7.

## 1. Требования

- Node 22.18 или новее. Он выполняет `.ts` без сборки.
- Python с `huggingface_hub` — только для загрузки датасета.
- Docker или локальный Phoenix.
- Около 25 ГБ на диске: `test.csv` 116 МБ, пять архивов 9.4 ГБ, распакованные кадры 15 ГБ.
- Ключ Cerebras.

## 2. Зависимости

```bash
npm ci
```

## 3. Датасет

Нужны `test.csv` и все пять shard изображений. Одного нулевого не хватает: пул корпусов
набран по всему сплиту, поэтому manifest ссылается на кадры из любого архива.

```python
from huggingface_hub import hf_hub_download

names = ["test.csv"] + [f"images/test/{n:02d}.zip" for n in range(5)]
for name in names:
    hf_hub_download(
        repo_id="osv5m/osv5m",
        filename=name,
        repo_type="dataset",
        local_dir="tmp/datasets/osv5m",
    )
```

Распакуйте архивы внутрь `tmp/datasets/osv5m/images/test/`. Вложенность значения не
имеет: индекс изображений обходит директорию рекурсивно и связывает файл с строкой CSV
по имени.

```bash
cd tmp/datasets/osv5m/images/test && for z in 0*.zip; do unzip -q -o "$z"; done && cd -
```

Распаковка занимает около 20 минут. Архивы после неё можно удалить, они занимают 9.4 ГБ.

Каталог `tmp/` в `.gitignore`. Другое расположение задаётся переменной `OSV5M_DIR`.

## 4. Ключи

```bash
cp .env.example .env
```

Впишите `CEREBRAS_API_KEY` в `.env`. Файл `.env` в `.gitignore`, в репозиторий он не
попадает. Скрипты `npm run` читают его через `node --env-file-if-exists=.env`.

## 5. Проверка корпусов

Команда читает только локальные файлы и не обращается к API.

```bash
npm run sample
```

Ожидаемый вывод:

```text
dataset  tmp/datasets/osv5m
pool     210122 images on disk of 210122 rows in test.csv
review   1725 frames kept, 283 dropped
curated  1725 frames in the pool both corpora are cut from
eval     n=863 seed=split-v1 fp=8658ddd26d80 strata=598 countries=147
train    n=862 seed=split-v1 fp=d2d163d965f5 strata=584 countries=144
         283 frames dropped by review at freeze time
link     eval->d2d163d965f5 train->8658ddd26d80  (paired)
review   0 dropped and 0 unreviewed frames in the corpora, 0 kept frames outside them
balance  country gap=109 floor=109 worst=ST+3  (optimal)
overlap  ids=0 sequences=0 creators=0 cells=0  (disjoint)
ready    every frame is on disk, reviewed, kept, and in exactly one balanced half
```

На Windows путь в первой строке печатается с обратными слэшами. Значение имеют четыре
строки:

- `fp=` совпадает с числом из [Оценка агента на OSV-5M](osv5m-eval.md#два-корпуса) — значит,
  прогон оценит те же 863 кадра.
- `(paired)` означает, что корпуса заморожены одним запуском и сверены друг с другом.
- `(disjoint)` означает, что корпуса не делят ни кадр, ни проезд, ни автора, ни ячейку
  сетки 25 км.
- `(optimal)` означает, что части сходятся по странам настолько, насколько это возможно на
  этом пуле; `gap` выше `floor` был бы дефектом разбиения.

Строка `review` должна показывать три нуля. Ненулевое первое или второе число означает, что
в корпусе лежит отброшенный или непросмотренный кадр; ненулевое третье — что одобренный
кадр в корпуса не попал. В любом случае команда падает.

Если команда сообщает о недостающих изображениях, повторите шаг 3.

## 5a. Сборка кадров

Кадры корпусов коммитятся, поэтому в свежей копии они уже на месте. Пересобрать папку
нужно после перезаморозки или правки поворотов:

```bash
npm run collect
```

```text
eval   863 frames -> benchmark/images/eval
train  862 frames -> benchmark/images/train
---
copied  1725 frames, 87 MB, 1346 uploaders
turned  196 frames upright per benchmark/samples/rotated.txt
dropped 283 moved and 0 written to tmp/dropped
removed 1992 frames that no corpus claims any more
```

Команда — единственный писатель `benchmark/images/`. Она собирает папку заново, сверяет
каждую копию по sha256, переносит забракованные кадры в `tmp/dropped/` и удаляет всё
остальное. Забракованный кадр переносится, а не удаляется: осмотр можно захотеть
пересмотреть, а `tmp/` не коммитится. Непросмотренный кадр удаляется — он остаётся в shard
датасета, откуда папку и собирают.

## 6. Phoenix

```bash
docker run -p 6006:6006 -p 4317:4317 -i -t arizephoenix/phoenix:latest
```

Без Docker:

```bash
uvx --from arize-phoenix phoenix serve
```

Пакет на PyPI называется `arize-phoenix`. Команда `uvx phoenix serve` ставит посторонний
пакет `phoenix`, в котором нет исполняемых файлов, и завершается сообщением
`Package \`phoenix\` does not provide any executables.`

Откройте `http://localhost:6006`. Без примонтированного тома данные пропадают после
остановки контейнера. Для сохранения примонтируйте volume в `/mnt/data`.

## 7. Прогон

```bash
npm run experiment -- --name my-run-1
```

Скрипт создаёт dataset `osv5m-split-v1-n863-8658ddd26d80`, если его ещё нет, и
переиспользует его в следующие разы. Все прогоны на одном dataset сравнимы между собой.

Флаги:

| Флаг | Что делает |
|---|---|
| `--name` | Метка прогона. Занятое имя продолжает тот же эксперимент. |
| `--concurrency` | Параллельность, по умолчанию 8. |
| `--manifest` | Другой файл корпуса. Роль должна быть `eval`, иначе прогон останавливается до первого платного вызова. |
| `--backend` | Система памяти: `file` или `mem0`. |
| `--snapshot` | Замороженный снапшот памяти; без него прогон идёт без памяти. |
| `--recall` | Режим отбора подсказок, по умолчанию `all`. |
| `--two-step` | Сначала посмотреть кадр, затем искать в памяти по увиденному. |
| `--head N` | Считать только первые N id манифеста. |

Все стандартные OpenRouter-вызовы в одном процессе проходят через последовательную очередь.
Минимальный интервал между стартами задаётся `OPENROUTER_MIN_INTERVAL_MS` в `.env` и по
умолчанию равен 1000 мс. Это снижает burst-нагрузку на provider, но не отменяет его квоту.

`--two-step` добавляет второй vision-вызов на кадр. Без памяти он бессмысленен, а с
ranked или query-backend он обязателен: иначе поиску нечего подать на вход. Признаки
кешируются по версии prompt и по байтам кадра, поэтому прогон с памятью и прогон без
памяти задают один и тот же вопрос и платят за него один раз, а изменённый кадр получает
новое наблюдение.

`--head N` — это не корпус меньшего размера. Манифест отсортирован по id, а порядок id
никак не связан со страной, поэтому совпадение с train-корпусом по странам выполняется
для файла целиком, а не для его префикса. Префикс получает свой отпечаток: частичный
прогон — другой benchmark, и его числа нельзя записывать под числа полного.

В конце выводится сводка по метрикам и ссылка на страницу experiment в Phoenix.

Повторный запуск с тем же `--name` продолжает эксперимент, а не начинает новый: скрипт
доигрывает недостающие прогоны и дописывает недостающие оценки. Прерванный прогон так не
оплачивается второй раз. Флаги, отличные от записанных в эксперименте, останавливают
запуск и называют расхождение: одно имя не хранит две конфигурации.

Сводка читается с сервера, а не из памяти процесса. Оценки уходят в Phoenix по одной, и
после обрыва часть из них отсутствует. Строка `scores N/M` называет этот пробел, а
повторный запуск с тем же `--name` его закрывает и печатает полную сводку без единого
платного вызова.

## 8. Сверка

Базовых чисел для корпуса `8658ddd26d80` пока нет. Сделайте три прогона A/A подряд и
запишите `geoscore`, среднюю дистанцию и `acc_200km` в
[Оценка агента на OSV-5M](osv5m-eval.md). Разброс между этими тремя прогонами и есть
коридор шума; отличие внутри него — не эффект.

Числа корпуса на 200 кадрах для сверки не годятся: у него другой размер, кадры там
обрезались на 5% снизу, и общих кадров мало.

## 9. Обучение

```bash
npm run train
```

Команда идёт по train-корпусу и пишет уроки в память. Флаг `--limit N` берёт первые N
кадров того же замороженного корпуса, а не делает новый жребий. Файл должен иметь роль
`train`. Флаг `--two-step` работает так же, как в прогоне.

Жребия здесь нет намеренно. Раньше train-поток набирался на месте, с квотами по странам,
скопированными из eval-манифеста. Требование за этими квотами осталось: урок про страну,
которую benchmark не показывает, не может сдвинуть число, он только добавляет токены.
Теперь это требование выполнено раньше — разбиение пула даёт корпусам совпадающие доли
стран на этапе заморозки, и `npm run sample` это проверяет.

## 10. Новые корпуса

Замороженные списки меняйте отдельной командой и отдельным commit.

```bash
node src/sample.ts --freeze
npm run collect
```

Команда набирает оба корпуса за один запуск: только так они получают взаимную ссылку,
проверку разделения и общий баланс. Размер не задаётся флагом — он равен числу одобренных
кадров в `benchmark/samples/reviewed.txt` минус отбраковка. Заморозка идёт около 4 секунд:
она читает каждый кадр, чтобы найти нечитаемый файл и побайтовый дубль, и больше ничего.

Manifest ссылается на кадры, которые есть на диске. С неполным набором shard заморозка
останавливается и называет недостающие id, поэтому перед ней убедитесь, что `pool` в выводе
равен 210 122. Числа со старыми корпусами не сравнивайте.

Чтобы корпус вырос, нужен не флаг, а новая сессия осмотра: пул — это то, что осмотр
одобрил.

## 11. Замена кадра

Кадр, непригодный для benchmark, добавьте в `benchmark/samples/rejected.txt` строкой
`<id> <причина>` и перезаморозьте корпуса. Причина обязательна.

```bash
node src/sample.ts --freeze
npm run collect
```

Замены нет: пул конечен, поэтому корпуса становятся на один кадр меньше. Разбиение
считается заново, поэтому часть кадров может поменять корпус. Отпечатки корпусов меняются,
поэтому базовые числа надо пересчитать.

Пока забракованный кадр остаётся в корпусе, `npm run sample` падает и называет его id.

## 12. Ручной просмотр кадров

Все решения о кадре принимает человек, по одному кадру за раз: ориентацию, мусор в кадре,
нечитаемую сцену и выжженные координаты. Автоматического экрана нет. Осмотр не фильтрует
корпус, а создаёт его: пул корпусов равен списку одобренных кадров.

```bash
npm run review
```

Команда поднимает локальное приложение на `http://localhost:5173` и показывает кадры из
`benchmark/images/`. Порядок — сначала самые подозрительные по файлу
`tmp/analysis/updown.json`, если он есть; иначе по id. Управление — четыре стрелки или
четыре свайпа:

| Клавиша | Свайп | Действие |
|---|---|---|
| &uarr; | вверх | кадр годен, перейти к следующему |
| &darr; | вниз | отбраковать с причиной `drop`, перейти к следующему |
| &larr; | влево | повернуть на 90° против часовой, остаться на кадре |
| &rarr; | вправо | повернуть на 90° по часовой, остаться на кадре |
| L | — | список кадров, отброшенных в этой сессии |

Свайп считается от 48 пикселей по преобладающей оси, поэтому касание и мелкое движение
пальца ничего не меняют. Мышью работает то же движение с зажатой кнопкой. Пока открыт
список, свайп и стрелки не действуют.

Каждое решение сразу попадает в файл, поэтому сессию можно прервать и продолжить с того
же места:

- `benchmark/samples/rejected.txt` — отброшенные кадры, причина `drop`;
- `benchmark/samples/reviewed.txt` — просмотренные и оставленные кадры;
- `benchmark/samples/rotated.txt` — повороты, строка `<id> <градусы по часовой>`.

Кадр, названный в `reviewed.txt` или в `rejected.txt`, второй раз не показывается. Чтобы
посмотреть его снова, удалите строку. Строка в `rotated.txt` кадр не скрывает.

### Просмотр с телефона

```bash
npm run review -- --tailnet
```

Флаг публикует приложение в tailnet через `tailscale serve` и печатает адрес вида
`http://home.taild01509.ts.net/`. Порт прокси задаётся `REVIEW_TAILNET_PORT`, по
умолчанию 80: на 80 не нужен сертификат, а трафик и так шифрует WireGuard.

Прямой адрес `http://<tailnet-ip>:5173` с другого устройства не работает, хотя сервер
слушает все интерфейсы. Правила Windows Firewall для `node.exe` разрешают входящие
соединения только в профиле Public, а интерфейс Tailscale относится к профилю Private.
У `tailscaled` разрешение есть для любого профиля, поэтому прокси работает без правки
firewall и без прав администратора.

Порт в прокси берётся из самого процесса, поэтому он не может указывать на порт, где
ничего не слушает. Такую опечатку с телефона не видно: браузер показывает только ошибку
соединения. Прокси снимается командой `tailscale serve --http=80 off`; приложение
пытается сделать это само при выходе по Ctrl+C.

Поворот считается от исходного кадра датасета, а не от уже повёрнутого файла: четыре
нажатия стрелки дают одно перекодирование, а возврат к 0° восстанавливает исходные байты
кадра. Повёрнутый кадр остаётся в корпусе, и `npm run review` сразу перезаписывает файл в
`benchmark/images/`, поэтому модель видит тот же повёрнутый кадр без всякого поиска угла на
стороне. Отпечаток корпуса при этом не меняется, а пиксели меняются, поэтому базовые числа
надо пересчитать.

Отброшенные кадры требуют перезаморозки корпусов по шагу 11: пока забракованный кадр
лежит в корпусе, `npm run sample` падает и называет его id. После перезаморозки
`npm run collect` соберёт `benchmark/images/` заново, применит повороты и перенесёт
отброшенные кадры в `tmp/dropped/`.
