# Базовый процесс инференса Loci

## Цель

В рабочем режиме Loci получает от пользователя фотографию, анализирует видимые признаки и
возвращает наиболее вероятное местоположение. Для поиска релевантного опыта агент использует
`memory_retrieve`, а для разрешения топонимов и проверки координат при необходимости —
`geocode_search` и `geocode_reverse`.

Инференс не изменяет память и не создаёт обучающий эпизод. Обучение выполняется отдельным
[процессом](/workflows/train.md).

## Допущения

- На вход поступает одна фотография без надёжных координат в метаданных.
- Пользователь не предоставляет истинное местоположение вместе с запросом.
- Агент анализирует только доступное изображение и сведения, явно переданные пользователем.
- Извлечённые из памяти записи являются подсказками, а не доказанными фактами.
- В рабочем цикле доступны только `memory_retrieve`, `geocode_search` и `geocode_reverse`.
- Один запрос обрабатывается последовательно одним агентом.

## Общая схема

```text
фотография пользователя
    → наблюдения
    → поиск релевантного опыта в памяти
    → географические гипотезы
    → геокодинг выбранной гипотезы, если нужен
    → ответ пользователю
```

## Состояния цикла

```text
STARTED → OBSERVED → REASONED → ANSWERED
```

| Состояние | Результат |
|---|---|
| `STARTED` | Получена фотография и создан контекст запроса. |
| `OBSERVED` | Зафиксированы видимые признаки без географического вывода. |
| `REASONED` | Получен релевантный опыт из памяти и выбрана итоговая гипотеза. |
| `ANSWERED` | Пользователю переданы местоположение, уверенность и краткое обоснование. |

## 1. Создание контекста

Для запроса создаётся временный контекст:

```text
attempt_id
image_ref
created_at
```

`attempt_id` связывает обращения к памяти в рамках одного запроса. `image_ref` указывает на
исходную фотографию, но не передаётся в память вместе с бинарным изображением. Контекст нужен
только на время выполнения инференса и сам по себе не архивируется.

## 2. Первичное наблюдение

Сначала агент описывает только различимые признаки фотографии без привязки к месту:

- ландшафт, рельеф, климат и погоду;
- растительность, почву и воду;
- архитектуру и строительные материалы;
- дороги, разметку, знаки и инженерную инфраструктуру;
- транспорт и номерные знаки;
- язык, письменность и читаемые названия;
- свойства изображения и возможные артефакты съёмки.

Наблюдения разделяются на положительные и отрицательные. Отсутствие объекта считается
отрицательным признаком только тогда, когда соответствующая часть сцены достаточно хорошо видна.
Интерпретации вроде «похоже на Северную Америку» не записываются как наблюдения.

## 3. Обращение к памяти

После первичного наблюдения агент вызывает [`memory_retrieve`](/tools/memory_retrieve.md) с
запросом по наиболее различающим признакам фотографии. В память передаются текстовые наблюдения
и `attempt_id`, но не сама фотография.

При необходимости допускается второй смысловой проход после появления географических
кандидатов: агент запрашивает признаки и исключения, позволяющие различить эти варианты.

Для использованных записей агент сохраняет в текущем контексте:

```text
memory_evidence[]
  reference
  summary
  influence
```

Запись из памяти влияет на гипотезу только тогда, когда согласуется с видимыми признаками.
Противоречия отмечаются явно. Порядок выдачи и отсутствие результатов сами по себе не являются
основанием для географического вывода.

Если `memory_retrieve` недоступен, агент продолжает анализ фотографии самостоятельно и снижает
уверенность с учётом отсутствия релевантного опыта.

## 4. Формирование гипотез

Агент формирует не более трёх ранжированных кандидатов. Для каждого кандидата учитываются:

- признаки в пользу;
- признаки против;
- использованные записи памяти;
- доступный уровень точности: страна, регион или населённый пункт;
- оставшаяся неопределённость.

После сравнения выбирается одна итоговая гипотеза. Агент не имитирует точность: если надёжно
определён только регион, это явно отражается в уверенности и радиусе неопределённости.

## 5. Геокодинг

Геокодинг применяется только после формирования географической гипотезы:

- [`geocode_search`](/tools/geocode_search.md) преобразует выбранный топоним или адрес в
  координаты и помогает разрешить неоднозначность названия;
- [`geocode_reverse`](/tools/geocode_reverse.md) проверяет административную принадлежность
  выбранных агентом координат.

Визуальное описание фотографии не используется как запрос к геокодеру. Несколько результатов
`geocode_search` рассматриваются как неоднозначность, а не как рекомендация выбрать первый.
Геокодер подтверждает существование места, но не доказывает, что фотография сделана там, и
сам по себе не повышает уверенность агента.

Если геокодинг недоступен, агент самостоятельно выбирает ориентировочную точку внутри наиболее
вероятного места и увеличивает пространственную неопределённость.

## 6. Ответ пользователю

Ответ содержит одну итоговую оценку местоположения:

```text
selected_location
  coordinates
    latitude
    longitude
  country
  region
  locality

confidence_by_level
  country
  region
  locality

spatial_uncertainty
  radius_km
  coverage

evidence_summary
alternatives[]
```

Координаты представляют лучшую точечную оценку агента, а не гарантированное место съёмки.
`confidence_by_level` отражает уверенность в административных уровнях, а
`spatial_uncertainty` — вероятный географический разброс вокруг выбранной точки.

В `evidence_summary` кратко перечисляются главные видимые признаки и влияние релевантной памяти.
`alternatives` содержит только правдоподобные варианты, если неоднозначность существенна.

После отправки ответа цикл переходит в `ANSWERED` и завершается. Агент не вызывает
`memory_store` или `episode_store` и не изменяет записи, полученные через `memory_retrieve`.

## Инварианты процесса

- Сначала фиксируются наблюдения, затем формируются географические гипотезы.
- Память используется как источник релевантного опыта, а не готового ответа.
- Геокодинг применяется к уже сформированной гипотезе, а не для перебора возможных ответов.
- Итоговый ответ содержит одну точечную оценку и явно выраженную неопределённость.
- Изображение, ответ и история запроса не сохраняются инструментами инференса.
- Рабочий цикл не вызывает `memory_store` и `episode_store`.

## За пределами первой версии

- обработка нескольких фотографий одного места;
- запрос дополнительных изображений или уточнений у пользователя;
- обучение по пользовательской обратной связи внутри рабочего запроса;
- автоматическое архивирование истории инференса;
- использование внешних источников помимо памяти и геокодинга.
