# Отказ от geo-фильтрации observations

## Наблюдение

Попытка фильтровать model-generated observations по словарю стран, регионов, городов и континентов
смешивает разные классы сущностей и не имеет надёжного контекста. Одинаковые слова могут быть
частью вывески, названия бренда, исторического текста или визуального признака, а не географическим
выводом модели.

## Варианты

1. Расширять словарь и усложнять regex — сохраняет post-hoc фильтрацию, но увеличивает ложные
   срабатывания и всё равно не решает омонимию.
2. Оставить географическое решение модели и фильтровать только структурно — сохраняет фактический
   visual output, а приложение проверяет только контракт JSON и resource bounds.
3. Перенести semantic moderation в отдельный classifier — добавляет latency, стоимость и новый
   компонент без доказанной пользы для текущего memory loop.

## Вывод

Для текущего workflow выбирается второй вариант. Prompt может направлять модель к наблюдаемым
визуальным фактам, но runtime не должен удалять feature по содержимому, если JSON структурно валиден.
