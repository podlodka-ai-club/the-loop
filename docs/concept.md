# Loci

## Название

`Loci` — множественное число латинского слова `locus`, «место». Название отражает задачу
агента: находить место съёмки и накапливать знания о характерных признаках разных мест.

## Назначение

Loci — фоновый агент геолокации по фотографии. Он предназначен для определения наиболее
вероятного места съёмки, когда точные координаты и надёжные метаданные недоступны.

## Как работает

Агент изучает видимые признаки: ландшафт, климат, растительность, архитектуру, дорожную
инфраструктуру, транспорт, язык и другие локальные особенности. На их основе он формирует
кандидатов, выбирает наиболее вероятное место и кратко объясняет вывод.

## Идентификатор подключённой памяти

В workflow-полях `memory_snapshot_id` и tool-полях `snapshot_id` сохранено историческое имя
`snapshot_id`, но в текущей модели это **opaque ID привязки к выбранной системе памяти**. По этому
ID оркестратор разрешает конфигурацию и экземпляр `xmemory`, Cognee, Mem0 или другой реализации.

Этот идентификатор не означает версию данных, branch, checkpoint или snapshot внутри провайдера.
Провайдеру не требуется поддерживать создание, переключение, клонирование или rollback
снапшотов. Выбор одной привязки фиксируется на время конкретного workflow; смена привязки — это
изменение конфигурации оркестратора между запусками, а не операция памяти.

`null` означает запуск без подключённой памяти. Неизменяемым snapshot в документации остаётся
только `answer_snapshot`: это зафиксированный аудит одного solve, а не состояние внешней памяти.

[Production-инференс](workflows/inference.md), обучение и оценка памяти используют один [слепой цикл
геолокации](workflows/locate.md), чтобы сравнивать одно и то же поведение решателя.

## Обучение

[Обучение](workflows/train.md) последовательно проходит train-корпус. Для каждого примера агент
сначала решает задачу с выбранной привязкой к системе памяти. Ответ и все обращения к памяти
фиксируются, после чего агент получает ground truth и выполняет рефлексию.

Результатом рефлексии становятся короткие заметки для будущих задач.
[`memory_store`](tools/memory_store.md) добавляет их в ту же систему памяти. Внутри обучения нет
baseline-run и общего score.

## Оценка

[Оценка памяти](workflows/evaluate.md) выполняется отдельно от обучения на независимом
eval-корпусе. Сначала весь корпус проходит inference без памяти и даёт
`baseline_mean_distance_km`. Затем тот же корпус с той же runner-конфигурацией проходит с выбранной
системой памяти и даёт `memory_mean_distance_km`.

Разница показывает общий эффект retrieval-механизма вместе с содержимым выбранной системы. Score основан
только на [WGS84-геодезическом расстоянии](workflows/scoring.md). Во время обоих прогонов ground
truth раскрывается только scorer после фиксации ответа, а память не изменяется. После просмотра
отчёта оператор может вручную выбрать memory binding для production.

## Память

Память Loci — внешнее хранилище текстовых заметок, выбранное через memory binding. Во время решения
агент получает релевантные заметки через
[`memory_retrieve`](tools/memory_retrieve.md).

Извлечённые заметки используются как подсказки, а не как факты: агент сопоставляет их с текущей
фотографией. Production и evaluation только читают память; записи выполняются исключительно в
training-контуре после reveal.
