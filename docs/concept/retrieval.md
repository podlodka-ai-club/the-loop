# Три ступени

1. **Структурный фильтр по `trigger`** — отбираются уроки, чьи признаки совпадают с признаками задачи.
2. **Ранжирование** по произведению счёта урока и близости триггера.
3. **Бюджет** — в контекст уходит только top-k.

# Главный анти-паттерн

**Свалить всю память в контекст.** Схема работает на первых двадцати задачах и разваливается дальше: контекст распухает, релевантные уроки тонут среди нерелевантных, качество падает — и получается перевёрнутая кривая обучения, где чем больше опыта, тем хуже результат. Это самый частый способ провалить проект такого рода.

# Особенность геолокации: признаки задачи неизвестны заранее

В текстовых доменах триггер извлекается из формулировки задачи. Здесь на входе — фотография, и признаки («жёлтая разметка», «левостороннее движение», «кириллица на вывеске») сами являются результатом наблюдения.

Отсюда двухфазный проход:

- **Фаза наблюдения.** Агент описывает кадр в терминах фиксированного словаря признаков — без попытки назвать место. Дёшево и не требует опыта.
- **Фаза вывода.** По полученным признакам подтягиваются уроки, и уже с ними агент называет координаты.

Побочная польза: словарь признаков становится общим языком между наблюдением, триггерами уроков и отчётностью — по нему же удобно разбирать, на каких признаках агент систематически ошибается.

Открытый вопрос — фиксировать словарь признаков заранее или позволять агенту его расширять. См. [открытые вопросы](/open-questions.md).
