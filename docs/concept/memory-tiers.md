# Уровни

| Уровень | Что хранит | Зачем нужен |
|---|---|---|
| **Эпизодический** | Сырые траектории решения плюс вердикт грейдера | Материал для шага Retro, аудит и разбор задним числом |
| **Семантический** | [Карточки уроков](/concept/lesson-card.md) со счётом | Быстрый переиспользуемый опыт, подтягиваемый под задачу |
| **Процедурный** | Навыки — код, скрипты, чеклисты, которые агент написал себе сам | Обрезает и стоимость, и разброс результатов |

# Почему процедурный уровень важнее всего

Уроки на семантическом уровне надо каждый раз перечитывать и интерпретировать — это стоит контекста и допускает ошибку интерпретации. Навык исполняется.

Когда урок набирает достаточную статистику, консолидация превращает его в переиспользуемую процедуру: чеклист проверки признаков, скрипт предобработки кадра, готовая последовательность шагов сужения региона. Дальше агент не переоткрывает решение, а вызывает готовое.

Практическое следствие для демо: **стоимость задачи начинает падать одновременно с ростом качества**. Две кривые в разные стороны убеждают сильнее, чем любой нарратив о том, что агент «поумнел».

# Хранение

Уроки и навыки живут в git как markdown-файлы: человекочитаемые, ревьюабельные, откатываемые, с историей изменений. Это даёт три вещи, которых не даёт база данных:

- судья на демо может **открыть и прочитать**, чему агент научился;
- любое состояние памяти воспроизводится по коммиту — что критично для [чекпоинтов замера](/evaluation/measurement-protocol.md);
- откат отравленного урока — обычный revert.

Эпизодический слой в git не кладём: это объёмные логи траекторий, им место в отдельном хранилище со ссылкой по `task_id`.
