# Воспроизведение замеров памяти

## Что измерено

Пять прогонов на замороженном eval-корпусе. Все — `google/gemma-4-31b-it` через OpenRouter,
провайдер Novita, квантовка bf16, `temperature 0`, фиксированный seed.

| Прогон | Кадров | Медиана | GeoScore | Притяжение |
|---|---:|---:|---:|---:|
| baseline, без памяти | 863 | 702 км | 2696 | 5% |
| вся память, 73 урока | 863 | 1163 км | 2212 | 75% |
| top-5 без порога | 430 | 926 км | 2396 | 32% |
| top-5 со стоп-листом и порогом 2 | 430 | 739 км | 2552 | 16% |
| **контроль: подменённые регионы** | 430 | 750 км | 2566 | — |

**Притяжение** — доля предсказаний, попавших в один из 61 региона, названного уроками. Без
памяти это 5%, то есть примерно случайный уровень.

Главный результат — последняя строка. Прогон на уроках с подменёнными регионами
неотличим от прогона на настоящих: на 183 кадрах, получивших подсказки, медиана попарной
разницы 0.0 км, 52 кадра лучше против 49 хуже. Содержание уроков вклада не даёт; работает
форма — список названных мест с уверенным утверждением при каждом.

## Что нужно на машине

**Датасет.** `tmp/datasets/osv5m/test.csv` — метки. Кадры корпусов коммитятся в
`benchmark/images/`, поэтому shard-архивы нужны только для пересборки корпуса, не для
прогона. См. [воспроизведение benchmark](/benchmark/reproduce.md).

**Phoenix.** Локальный сервер на `localhost:6006`:

```bash
uvx --from arize-phoenix phoenix serve
```

Пакет на PyPI называется `arize-phoenix`; `uvx phoenix serve` ставит посторонний пакет без
исполняемых файлов.

**`.env`:**

```
OPENROUTER_API_KEY=...
GEOLOCATE_MODEL=google/gemma-4-31b-it
OPENROUTER_PROVIDER=Novita,Venice
OPENROUTER_QUANTIZATION=bf16
GEOLOCATE_TEMPERATURE=0
GEOLOCATE_SEED=1
```

Снапшот назван хешем собственного содержимого, поэтому два прогона с одинаковым именем

## Команды

Обучение — 75 кадров, топ-15 стран eval по пять кадров на страну:

```bash
npm run train -- --countries-from benchmark/samples/osv5m-v4-eval.txt \
  --countries 15 --per-country 5 --snapshot-every 25
```

Перед обучением отложи рабочий стор, иначе новые уроки допишутся к старым:
`mv data/memory/live.jsonl data/memory/<имя>.jsonl`.

Базовый прогон:

```bash
npm run experiment -- --concurrency 1 --name baseline-v4-eval-863
```

Вся память в промпте:

```bash
npm run experiment -- --snapshot f6bf9c5ea31f --recall all \
  --concurrency 1 --name memory-73-region-863
```

Отбор пяти уроков по совпадению признаков:

```bash
MEMORY_RECALL_LIMIT=5 npm run experiment -- --snapshot f6bf9c5ea31f \
  --recall top --two-step --head 430 --concurrency 1 --name memory-top5-twostep-430
```

То же со стоп-листом и порогом в два совпадения — стоп-лист уже заморожен, пересчитывать
его нужно только после смены промпта наблюдения:

```bash
npm run stopwords
MEMORY_RECALL_LIMIT=5 npm run experiment -- --snapshot f6bf9c5ea31f \
  --recall top --two-step --head 430 --concurrency 1 --name memory-top5-threshold2-430
```

Контроль с подменой:

```bash
npm run shuffle-memory -- --snapshot f6bf9c5ea31f
MEMORY_RECALL_LIMIT=5 npm run experiment -- --snapshot 939a81e8e4e4 \
  --recall top --two-step --head 430 --concurrency 1 --name shuffled-top5-threshold2-430
```

## Наблюдения и их кэш

`--two-step` добавляет вызов перед ответом: модель перечисляет видимые признаки по двенадцати
обязательным слотам, и этот список служит запросом к памяти. Без него у ранжирования нет
входа, а `top` вырождается.

Результат наблюдения кэшируется в `tmp/cache/observe/` по паре «версия промпта, байты кадра».
Причины две. Прогон с памятью и прогон без неё обязаны наблюдать одинаково, иначе сравнивать
нечего. И платить за наблюдение дважды — удваивать стоимость каждого сравнения.

Ключ построен на байтах, а не на пути: кадр, повёрнутый при осмотре, получает новый ключ сам
собой, и устаревшее наблюдение не переживёт картинку, которую описывает. Смена промпта
наблюдения обесценивает весь кэш, что и требуется.

Кэш не коммитится. На чистой машине первый прогон с `--two-step` соберёт его заново, заплатив
один вызов на кадр.

## Проверка чисел без прогонов

`data/runs/` содержит выгрузку всех пяти прогонов, строка на кадр: предсказание, ошибка в
километрах, число и идентификаторы подсказок, фактический провайдер. Кадр без ответа сохраняет
причину сбоя, а не исчезает — иначе знаменатель молча уменьшается.

Числа таблицы пересчитываются из этих файлов, Phoenix для этого не нужен.

`baseline-863.jsonl` содержит 54 кадра без ответа: они выпали по лимиту провайдера и
доигрывались отдельным прогоном, `baseline-fill-54.jsonl`. Полный базовый прогон — объединение
двух файлов. Так вышло потому, что Phoenix не переигрывает завершённый прогон и не даёт
удалить отдельный; после исправления в `src/task.ts` инфраструктурный сбой пробрасывается
наружу и подбирается повторным запуском с тем же `--name`.

Медиана в таблице считается как среднее двух центральных значений при чётном числе кадров.
Сводка самого прогона печатает медиану как элемент по индексу `floor(n/2)`, поэтому её числа
отличаются на единицы километров.

## Оговорка о переносимости

Числа получены на `google/gemma-4-31b-it` у провайдера Novita в квантовке bf16 при
`temperature 0`.

На другом провайдере или другой квантовке того же слага они сдвинутся: OpenRouter отдаёт этот
слаг с fp4, fp8 и bf16, и это разные веса. На другой модели изменится не только уровень, но,
возможно, и знак — вопрос «различает ли модель правильный урок от подменённого» задан
конкретной модели, а не архитектуре вообще.

Прикрепление провайдера вместе с квантовкой (`OPENROUTER_PROVIDER`, `OPENROUTER_QUANTIZATION`,
`allow_fallbacks: false`) существует ровно для того, чтобы сдвиг не произошёл незаметно.
Фактический провайдер ответа пишется в каждую строку выгрузки — если прогон уехал на другой
эндпоинт, это видно.

## Что известно про сами уроки

Замеры выше — про доступ к памяти. Отдельно измерено качество её содержимого:

- из 73 уроков шесть триггерятся только стоп-словами и совпадают с любым кадром, ещё
  шестнадцать имеют ровно один редкий токен. При пороге в два совпадения **22 урока
  недостижимы поиском в принципе**;
- 57 из 166 редких токенов в триггерах (34%) не встречаются ни в одном из 530 наблюдений.
  Рефлексия пишет `grassland`, `topography`, `plantation rows`; наблюдатель таких слов не
  употребляет.

Рефлексия и наблюдение не имеют общего словаря, потому что их никто не сводил: рефлексия
описывает кадр свободно, наблюдение заполняет двенадцать фиксированных слотов.
